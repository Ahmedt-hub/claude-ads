# Ads Landing Image: Arabic Long-Image Landing Pages

Turns product photos into a persuasive Arabic landing page delivered as ONE
long vertical image, generated by Nano Banana Pro in Gemini. Claude writes the
copy and the generation prompt; the user pastes it into Gemini with the same photos.

## Reference Files (read before working)

| File | Use it for |
|------|-----------|
| `assets/store-profile.md` | Fixed store facts. Never ask the user about anything in it. |
| `assets/copy-rules.md` | Angles, headlines, copywriting rules, banned claims |
| `assets/section-library.md` | Section blocks + which sections fit which product type |
| `assets/design-rules.md` | Photo handling, fidelity, seamless background, typography |
| `assets/prompt-template.md` | Exact output format of the final prompt + fix-up message |

Read `store-profile.md` first on every run. Read the other four before STEP 2.

## Workflow

### STEP 1: Analyze and ask (stop and wait)

1. Look at every uploaded photo. For each one note silently: what it shows
   (product alone, on a model, close-up, color variant, packaging, infographic).
   Identify photos by CONTENT, never by upload order.
2. Identify: product, category, every visible feature, variants/colors, likely
   buyer and user, and the core motive (PAIN = solves a problem, DESIRE = beauty,
   status, pleasure, gift).
3. Check photo cleanliness. If a photo has text overlays, icons, other people or
   a ready-made infographic, warn the user that Gemini may copy them, and offer to
   crop the product out (Claude can crop it with Python/PIL).
4. Reply in Arabic with:
   - 2 to 3 lines summarizing what you see (product, pieces, colors).
   - A numbered list of **maximum 7 questions**. Each question carries a
     suggested default in brackets `[...]` so the user can answer "موافق".
   - End with: `رد بالأجوبة، أو اكتب "قرر انت" لاعتماد الاقتراحات.`
5. STOP. Do not write the prompt until the user answers.

**Question 1 is ALWAYS the marketing angle** (see `copy-rules.md` → Angles):
2 to 3 angles, each with target buyer/user, emotional motive, sample headline.
Mark one as `[مقترح]` with a one-line reason rooted in local culture and real usage.

Then ask only what is missing and matters for THIS product, in this priority:
1. Offers in the order form: exact names and prices (the page must repeat them word for word)
2. Upsell in the form, if any
3. Variants: sizes (with fit info), colors not shown in photos
4. What customers ask in Messenger before ordering (real objections)
5. Real reviews, customer photos or comment screenshots (ask to upload them)
6. Facts needed for strong claims: time to result, coverage, durability, materials
7. A real reason for urgency (new batch, season, wedding season, Ramadan...)

Never ask about: things clearly visible in the photos, anything in `store-profile.md`.

If the user answers "قرر انت" or skips a question: use your default. Exception:
prices, offers, numbers, specs and guarantees are NEVER invented. Missing → leave
them out of the page and say so in the notes.

If the user already gave everything in the first message, skip STEP 1.

### STEP 2: Write the prompt

1. Lock the chosen angle. Every section, headline, review, urgency line and scene
   serves this angle. Two angles may be mixed only if they share ONE motive
   (example: home privacy + shop privacy = "privacy").
2. Select 6 to 8 sections from `section-library.md` using its selection guide.
   The first 9:16 screen follows the ABOVE THE FOLD rules in `copy-rules.md`.
3. Write the copy following `copy-rules.md`, in the dialect from `store-profile.md`.
4. Build the prompt with `prompt-template.md`, applying `design-rules.md`.
5. Self-check before sending (fix silently if any fails):
   - [ ] Reading ONLY the headlines tells the whole offer
   - [ ] Max 2 headlines are questions
   - [ ] No generic headline (ثقة عملائنا، كيف يعمل، المميزات، تفاصيل مدروسة)
   - [ ] No invented number, price, certificate, duration or medical claim
   - [ ] Offer names and prices match the form exactly
   - [ ] Cash on delivery is not mentioned anywhere
   - [ ] Every photo is described by content and used at least once
   - [ ] Every text line is short (about 6 words max) with explicit line breaks
   - [ ] No usage, scene or occasion that clashes with local culture
6. Output: the prompt in ONE code block, then max 5 short Arabic notes:
   assumptions to verify, example reviews to replace, what was left out and why,
   which photos to upload in Gemini.

## After Generation

When the user sends the generated image back:
1. Praise what works in one or two lines, then list concrete problems
   (product fidelity, text errors, boxes/bands, small text, culture mismatch).
2. Give a FIX-UP message (template in `prompt-template.md`) to paste in the SAME
   Gemini chat. Never ask to regenerate the whole page for small issues.
3. If a lesson applies to all future products, propose adding it to the reference
   files of this skill.

## Fallback: exact render

If Gemini keeps altering the product, offer to build the page directly as HTML
with the user's real photos (Arabic web font such as Cairo, feathered image edges,
one continuous gradient) and export a 1080px-wide PNG with Playwright. Product
fidelity and Arabic text are then exact.

## Requirements

- Gemini with **Nano Banana Pro** (Gemini Pro subscription). The free/basic model
  redraws the product when given several photos.
- The user uploads the same photos in the Gemini chat together with the prompt.
